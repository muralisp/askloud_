Why Askloud

Built different

Privacy First

Zero data exfiltration

In every mode, only your plain-English question and field schema reach the API. Actual inventory data, cloud API responses, and CLI output stay entirely on your machine.

Translation Engine

LLM as syntax translator

Natural language becomes a structured query plan or native CLI command, executed locally by the Python engine. Not a data processor — a translator.

Multi-Cloud

Rosetta Stone for cloud

Normalizes disparate data models across AWS, GCP, and Azure. Ask about a resource without knowing or caring which cloud it lives in.

Agentic Terraform

Query, then change

Set tags, create resources from HCL templates, or destroy them through a guided plan-and-confirm flow. DynamoDB updates automatically after apply.

Cost Optimized

Aggressive token savings

Direct search bypasses the LLM at $0. No RAG, no chat history, no embedding overhead. Prompt caching reuses system context across turns.

Shell Native

Unix pipeline compatible

Pipe output through grep, awk, or wc with | cmd. Prefix ! to run raw shell commands directly inside the Askloud prompt.

No-Code Config

Columns without PRs

Adding or removing an output field is a one-line .conf edit. Field names resolve automatically from nested paths, tag keys, and aliases.

Event-Driven

Inventory that self-updates

tfstate writes and EC2 state changes flow through EventBridge → Lambda → SQS → DynamoDB in seconds. No scheduled polling, no manual syncs.

Kubernetes Ready

One-command deploys

Production deployments on EKS, AKS, and GKE via a single script per cloud. GitHub Actions builds and pushes; ArgoCD auto-syncs the Helm release.

Shift-Left

Six validation layers

fmt, tflint, checkov, a Pydantic schema contract, OPA tag policy on real plan output, and post-apply drift reconciliation — issues caught before production.

Event-Driven Inventory

Inventory that updates itself

Zero scheduled polling. Zero manual syncs. Real-time accuracy.

terraform apply→ tfstate → S3→ EventBridge→ Diff Lambda→ SQS (UPSERT / DELETE)→ Router Lambda→ DynamoDB
Diffs new tfstate against DynamoDB itself — not S3 versioning — so the pipeline self-heals even if an event is missed.
EC2 state change→ EventBridge→ EC2 Events Lambda→ SQS (DELETE)→ Router Lambda→ DynamoDB
Terminated instances leave inventory immediately — independent of the next tfstate write. Upserts are SHA-256 fingerprinted; deletes are soft with a 7-day TTL.
Agentic Terraform

The architecture of safe change

From query to apply — with a confirm gate at every step.

i

Resolve workspace

Looks up the Terraform path, S3 tfstate location, and AWS profile for the target resource.

ii

Read tfstate

Finds the exact resource address — module.x.aws_instance.y — matching the inventory record.

iii

Edit or create

Patches the .tf file in place with a unified diff, or renders new HCL from a template.

iv

Plan

Runs terraform plan -target and waits for explicit user confirmation.

v

Apply

Runs terraform apply -auto-approve -target — only after both prior confirmations.

vi

Auto-sync

The Diff Lambda picks up the new tfstate and updates DynamoDB automatically, within seconds.

Quick Start

Running in seconds

# 1. Set your API key export ANTHROPIC_API_KEY=your_key_here # 2. Run the CLI ./run_askloud.sh # interactive inventory mode ./run_askloud.sh --live # interactive live mode ./run_askloud.sh "list stopped instances in production" # 3. Or run the web GUI docker-compose up gui → http://localhost:8000
pip install anthropic jmespath django whitenoise gunicorn export ANTHROPIC_API_KEY=your_key_here # configure the cloud CLIs you need aws configure # AWS az login # Azure gcloud auth login # GCP python3 askloud.py # interactive inventory mode python3 askloud.py --live # interactive live mode
# AWS EKS export ANTHROPIC_API_KEY=... ./deploy-eks.sh dev # or prod # Azure AKS / GCP GKE ./deploy-aks.sh dev ./deploy-gke.sh dev # pin a tag, or run terraform apply first IMAGE_TAG=v1.2.3 ./deploy-eks.sh dev TF_APPLY=1 ./deploy-eks.sh dev

Cloud credentials from ~/.aws, ~/.azure, and ~/.config/gcloud mount read-only into the container.
